# M7 outbound workflow design review

Review date: 2026-09-20. Scope: the authorized outbound operations slice at `/operations/outbound`.

The workflow requests allocation and task execution but does not calculate inventory or movement in the browser. PostgreSQL allocation, active location/topology bindings, capability-qualified equipment, and the deterministic execution application service remain authoritative.

| Before                                                                                    | After                                                                                                                                  | Why                                                                                                           |
| ----------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Outbound shipment was visible only as backend contracts and a deterministic test scenario | A protected operator route creates an idempotent allocation, exposes its durable order/tasks, and executes one reviewed task at a time | Operators can use the product path without reviving the legacy React state machine                            |
| Operators could type a SKU with no visible relationship to current stock                  | The request uses distinct SKUs and aggregate quantities from available inventory projections                                           | The control communicates the current evidence while the backend still arbitrates concurrency and availability |
| Any location ID could be imagined by the presentation                                     | Destination choices require an available, topology-bound location with `outbound.stage` capability                                     | Customer configuration drives choices without hard-coded shipping codes                                       |
| Allocation and physical shipment could collapse into one opaque action                    | Allocation and execution are separate stages showing order ID, task count, remaining work, selected task, and equipment                | The consequential movement has a stable review boundary and supports split allocations                        |
| Service identity obscured the human actor                                                 | The authenticated session forwards a bounded operator identity to create and execute endpoints                                         | Allocation and shipment audit events remain attributable                                                      |
| Execution had no named confirmation contract                                              | The operator must check an authorization statement, provide an 8–500 character reason, and submit `execute_outbound_task`              | Accidental activation is harder and audit evidence captures intent                                            |
| Retrying allocation risked duplicate orders                                               | A stable idempotency key survives retries and changes only after an idle form edit                                                     | Ambiguous network outcomes do not create duplicate outbound work                                              |
| Completion gave no direct route to the persisted outcome                                  | The success status links to the inventory projection after every allocated task completes                                              | Operators verify the system-of-record result rather than trusting button state                                |
| No small-screen outbound proof existed                                                    | Chromium verifies the complete workflow, axe, and 390 × 844 reflow without page overflow                                               | Responsive and semantic requirements are executable                                                           |
| Six mobile navigation items compressed into multi-line labels                             | Navigation items remain single-line and scroll within the labelled navigation region                                                   | Labels stay readable without creating page-level horizontal overflow                                          |

Motion decision: allocation and execution are high-frequency operational actions, so state changes are immediate and text-driven. No progress animation or decorative motion was added. Only the shared 160 ms press response remains, and reduced-motion preferences remove its transform.
