# M7 topology map design review

Review date: 2026-09-19. Scope: the first product-operations visualization slice at `/operations/warehouse`.

The map is a read-only projection consumer. PostgreSQL topology and operations projections remain authoritative; SVG coordinates, node selection, and schematic fallback never change routing, inventory, task, or equipment state.

| Before                                                       | After                                                                                                                                                   | Why                                                                                                 |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Legacy SVG and React state jointly implied warehouse truth   | A dedicated operations route consumes versioned topology, task, inventory, and edge-status projections                                                  | Presentation cannot define connectivity or operational outcomes                                     |
| Operations projection discarded persisted node positions     | Optional validated `coordinateSystem`, `x`, `y`, and `z` presentation coordinates cross the read boundary                                               | Customer layouts can render without hard-coding the demo warehouse                                  |
| Missing coordinates prevented a useful map                   | A deterministic, explicitly labelled schematic fallback arranges nodes without changing graph connectivity                                              | The console remains useful while making the evidence boundary visible                               |
| Directed lines ended at node centers, hiding arrowheads      | Edge segments stop at node boundaries and retain visible directional markers                                                                            | Direction is an operationally meaningful property, not decoration                                   |
| Equipment assignment could be mistaken for physical position | The map places equipment only from timestamped, topology-qualified observations and labels stale evidence as last-known                                 | Assignment is not evidence of physical location                                                     |
| Map-only visual encoding                                     | Native node-selector buttons, `aria-pressed`, a live inspector, SVG title/description, text metrics, and an accessible projection page remain available | Keyboard and assistive-technology users receive the same facts without relying on color or geometry |
| Fixed purple legacy scrollbars                               | Scrollbars use light/dark design tokens, with hover styling limited to fine pointers                                                                    | Theme cohesion improves without creating touch hover artifacts                                      |
| No warehouse-map browser gate                                | Chromium verifies axe, configured-coordinate rendering, truthful missing-position messaging, and 390 px reflow                                          | The primary accessibility and responsive assumptions are executable                                 |

Motion decision: the map intentionally has no continuous vehicle or route animation. Operators may view it throughout a shift, and the current durable observation model is a latest-state projection rather than a continuous animation stream. High-frequency node selection uses immediate state changes with only the shared 160 ms press feedback; reduced-motion mode removes the transform.
